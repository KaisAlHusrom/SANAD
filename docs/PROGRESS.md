- **This session (2026-08-09): P8.8 — platform primitives (money · sequence · audit) — BUILT in three sequentially-green stages, plus the request-context seam and the first real audited write path. The platform can now price a line, number a document, and prove who changed what from where — the three things every commercial phase after this one assumes exist.**
  - **`@sanad/money` (44 tests).** Integer **minor units + ISO code**, never a float. Framework-free on purpose — no Nest, no drizzle, no zod — so `apps/admin-portal`, `apps/website` and the P8.21 client portal render money through the SAME code the services price with (F8/F9); the shapes live in `@sanad/contracts` (U3). Ships `rounding` (4 explicit modes, symmetric about zero — JS `Math.round(-2.5) === -2` would make a refund round differently from the charge it reverses), `money-math` (incl. **`allocate`**, largest-remainder, so splitting a total across a payment schedule loses no minor unit), `apply-tax` (exclusive **and** inclusive, `net + tax === gross` always), `line-total`/`summarize` (tax applied ONCE to the summed net, never per line), `format-money` (cached `Intl` per locale+currency+style, `numberingSystem:'latn'` — the locked U8 western-numerals decision) and `parse-money` (Arabic-Indic digits, Arabic decimal/thousands marks, bidi marks).
  - **The test that earned its keep:** `1.005 SAR` must be 101 halalas. `1.005 * 100 === 100.49999999999999` in IEEE-754, so rounding the raw product silently loses a halala on every three-decimal price a human types. `fromMajor` now re-quantises with `toPrecision(15)` before rounding; a regression spec pins it. **This was caught by a spec, not by review** — which is the argument for writing the awkward cases first.
  - **`@sanad/sequence` (19 tests).** `sequence_counter` shared fragment (mounted per service, MS5) + a **single-statement** allocator: `insert … on conflict do update set last_value = last_value + 1 returning last_value`. **Deliberate deviation from the plan's `SELECT … FOR UPDATE`** (`02-mvp.md:135`), recorded so it is never re-litigated: it is one round trip inside a lock the caller already holds, and — decisively — `RepoDb`, what `TransactionRunner.run` yields (N14), exposes **no `execute`**, so raw locking SQL cannot be issued through the seam an application service is allowed to hold. `periodFor` keys on the **UTC** year (the DB writes UTC), and padding is a MINIMUM so the 10 000th proposal of a year is `PRO-2026-10000`, not a truncated collision.
  - **The phase's named acceptance proof, and proof that the proof works.** 20 real concurrent connections, each its own transaction, allocating from one `(entity, period)`: the returned multiset is exactly `1…20` — no gap, no duplicate. Plus the case that defines the word: **allocate → rollback → allocate returns the SAME number**, because the counter moves inside the caller's transaction. Then the assertion was proven to bite — a deliberately non-atomic read-then-write allocator run through the identical harness produced **17 duplicates of 20**. A concurrency test that has never seen the bug it guards is decoration.
  - **`@sanad/audit` (38 tests) — the evidence layer, built before the thing it protects (P8.14).** `audit_log` fragment + **database-enforced** append-only: a `before update or delete` trigger raising `restrict_violation`, shipped as `AUDIT_IMMUTABILITY_SQL` (drizzle-kit cannot generate a trigger, so the constant is the single source every adopting service applies in a `--custom` migration). The store has no `update` and no `delete` **by construction**, so the mutation the trigger refuses cannot even be expressed. Also: `redact` (deny-list on KEYS, cycle- and depth-safe — the audit row is the one place the platform deliberately copies whatever a write contained, which makes it the easiest place for a credential to land in plain text, N13), `diffFields` (only what moved; an added key reads `before: null`, a removed one `after: null`), the ALS-backed `AuditRecorder`, `@Audited()`, and an interceptor bound via **`APP_INTERCEPTOR`** — the one registration form that reaches a hybrid app's **RMQ** handlers, which is where every write in this platform actually arrives (`app.useGlobalInterceptors` binds HTTP only, as every service's `main.ts` already notes).
  - **The trap this design turns on, written down because it is invisible.** An interceptor that calls `als.run(scope, () => next.handle())` opens the scope around _building_ the observable, not around _running_ the handler — `next.handle()` is subscribed after every interceptor has returned, so the handler executes outside the scope and **every actor is silently null**. The scope must wrap the **subscription**. The naive form was written deliberately once to check the specs bite: **5 of 8 failed**, then it was reverted.
  - **Two ways in, on purpose.** `record()` buffers and the interceptor flushes after the handler; **`recordWithin(tx, …)` writes inside the caller's transaction**, so the business row, its Outbox event and its audit row commit or roll back as ONE. Settings uses the latter — proven both ways: a committed write has its row, a rejected write leaves none claiming it happened. And a failed audit write **never** fails the request: the trail records what the product did, it must not become a new way for the product to refuse.
  - **The request-context seam — the gap that blocked everything.** Nothing in the platform captured **ip / user-agent / request-id**: `IdentityContext` is `{userId, roles, permissions, email?}` and the gateway forwarded exactly two RMQ headers.
