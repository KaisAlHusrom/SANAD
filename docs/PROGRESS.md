(2) **Nav/IA deferred to me → Content hub page**: keep one `nav.content` sidebar entry; `/content` renders a card grid (`CONTENT_AREAS`) routing to each domain (design-spec §4 faithful, no `NavItem` schema change, scales to 9+ domains; only built areas listed → no dead links). **By-pattern (the load-bearing realizations — every later content stage reuses these):** (a) **The DynamicForm form-shape ≠ the contract shape.** The kit binds translatable fields to `translations.<locale>.<field>` (not the contract's top-level `LocalizedText {ar,en}`), AND native number inputs register as strings. So each vertical has a **form-shaped Zod schema** (`schema/*-form.zod.types.ts`) — translatable fields nested under `translations`, `z.coerce.number()` for numbers, `'' | uuid` for media ids — distinct from the contract upsert schema, plus a tiny set of **shared pivot helpers** (`localized-form.ts`: `toLocalizedFormRecord` / `toLocalizedUpsertBody` / `localizedFormSchema` / `phantomTranslatableKeys`). The kit's translatable `FieldConfig.name: Path<TValues>` needs the bare key as a real path, so the form schema spreads **literal-keyed phantom** `<key>: z.string().optional()` placeholders (generic helper preserves the literal union; the real data lives under `translations`). (b) **Default-locale-required, secondary-optional:** `localizedFormSchema` requires a "required" translatable field only in the **default locale (ar)**; en may be empty (falls back via `pickLocalized`) — Arabic-first, and doesn't block a save on incomplete English. (c) **`MediaIdPickerField` (new shared primitive):** the shipped `MediaPickerField` is URL-valued, but content stores media **uuids** (`coverMediaId`/`avatarMediaId`) — added an id-valued picker resolving the thumbnail via a new `getMediaLookupById` endpoint on the shared `media-lookup.api` (W5; never the media module's api). (d) **Coded enums = plain `<select>`** (W5 — ServerSelect is only for backend-sourced pickers); **`featured` = inline Switch** wired to the update mutation, perm-gated (W6); **per-locale LocaleTabs** for translatable edits (W6). (e) **Each mutation publishes `content.<entity>.changed`** (W4); the update body is `Omit<…UpdateRequest,'id'>` (PATCH `/:id`), so the inline featured toggle sends a partial `{ featured }`. (f) **No `/manage` for flat collections** — services/testimonials/faqs/team reuse the public `GET` list (no draft concept); only portfolio/blog (Stages 2–3) have a draft-visible `/manage` admin list. (g) **No gateway routes touched → no Postman drift (DOC2);** foundation files untouched (additive wiring only).
