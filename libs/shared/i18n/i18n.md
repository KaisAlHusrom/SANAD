# `@sanad/i18n` — the backend's Arabic-first message layer

> Rule: **U24** (every user-facing backend message is a localized key, never prose).
> Companions: U8 (ar default + key parity), N9 (the response envelope), MS4 (forwarded headers).

## Purpose

The backend is **Arabic-first exactly like the frontend**. Nothing in a service may emit
user-facing English prose. A service emits a stable **`messageKey` + `params`**; the text lives
here, in the `ar`/`en` catalogs, and is rendered **once, at the gateway edge**, in the locale the
caller asked for.

```
admin portal / website          gateway (the ONLY renderer)              service
  i18n.language                   resolveRequestLocale(headers)            rpcError(404, 'media.notFound', {id})
      │                                    │                                        │
      └── x-sanad-locale ─────────────────▶├── ResponseEnvelopeInterceptor ─────────┤ (RMQ headers carry
                                           │     translate(envelope.message)        │  x-sanad-locale too)
                                           └── AllExceptionsFilter                  │
                                                 translate(messageKey, params) ◀────┘
```

Payload-embedded text (an integration test result, later an email body) can't be reached by the
edge renderer — the service translates it itself, from the **same** forwarded locale.

## What lives here

| Path                                 | What                                                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| `lib/catalog/ar.catalog.ts`          | **The source of truth for the key tree.** `MessageKey` is derived from it.                |
| `lib/catalog/en.catalog.ts`          | Typed `Record<MessageKey, string>` — a missing translation is a **compile error**.        |
| `lib/catalog/catalog.parity.spec.ts` | Key parity, no empties, same `{placeholders}` in both, and "ar actually contains Arabic". |
| `lib/catalog/catalogs.ts`            | The locale → catalog lookup.                                                              |
| `lib/translate/translate.ts`         | `translate(key, locale, params?)` + `translateMessage(msg, locale)`.                      |
| `lib/locale/request-locale.ts`       | `resolveRequestLocale(headers)`, `localeToHeaders(locale)`, re-exports `LOCALE_HEADER`.   |
| `lib/errors/localized-errors.ts`     | `rpcError(status, key, params?)` (services) and `httpError(...)` (the gateway).           |

The header name (`x-sanad-locale`) and the string→`Locale` narrowing (`toLocale`,
`resolveLocale`) live in **`@sanad/contracts`**, not here (U3): the browser apps must set the same
header without pulling this NestJS-dependent package into their bundle.

## Contracts used

- `Locale`, `DEFAULT_LOCALE`, `LOCALE_HEADER`, `toLocale`, `resolveLocale` — `@sanad/contracts`.
- `LocalizedMessage` (`{ messageKey, params? }`) + `isLocalizedMessage` — the shape that crosses
  both the RMQ and HTTP boundaries.

## Locale resolution

`x-sanad-locale` → `accept-language` (first supported tag, `en-GB` → `en`) → **`ar`**.
The in-app language beats the device (F11), and Arabic is sent **explicitly**, never implied.

## How to add a message

1. Add the key + Arabic text to `ar.catalog.ts` (this creates the `MessageKey` member).
2. Add the English text to `en.catalog.ts` — the compiler demands it.
3. Throw/return it: `throw rpcError(HttpStatus.NOT_FOUND, 'your.key', { id })`.
4. Never format the sentence at the call site; put the whole sentence in the catalog and pass
   values as `params` (`{name}` placeholders).

**Entity-specific keys beat generic ones.** Arabic doesn't tolerate an English noun pasted into a
template, so `content.notFound.blogPost` exists rather than `content.notFound` + an entity param
(see `content-errors.ts`).

## Deliberate behaviours

- **Unknown key → returned unchanged.** A not-yet-migrated literal degrades to today's prose
  instead of showing the user a raw key.
- **Missing param → placeholder stripped**, never `{id}` leaked to a user.
- **Vendor errors keep their own words.** An AWS/SMTP failure renders as the localized line plus
  the raw SDK text in a separate `detail` field — on **both** `IntegrationTestResult` (Test
  connection) and `StorageCorsStatus` (the CORS check) — because the owner needs "which key is
  wrong" and only the vendor can say it (U24e).
- **Internal invariants stay English.** `insert returned no row` is not user-facing; it surfaces
  as the localized generic 500 (U24f).

## Consumers

`@sanad/util` (response interceptor, exception filter, Zod pipe, Postgres error map), the
api-gateway (`forwardHeaders`, `@RequestLocale`, `toHttpException`, guards), and all five
services' error factories + `testConnection` adapters.
